glib-log-interposer
===================

When launching Linux GTK applications from the terminal, these applications have the bad habit of cluttering the terminal with useless info/warning debug messages. For example, just launching `gedit` from the terminal on Ubuntu 22.04 prints this line three times to `stdout`:
```
** (gedit:162753): WARNING **: 18:12:31.170: Could not load theme icon text-x-generic: Icon 'text-x-generic' not present in theme Adwaita
```
And that is just the output that is printed during application startup; even more is printed while the application is running.

This project is a simple Linux shared library that is written to be used as an interposer (by defining the `LD_PRELOAD` environment variable). When used as an interposer, the library is automatically loaded into the address space of all user processes in the system. When loaded into GTK applications, it intercepts the functions that are responsible for the debug output and prevents the original functions from being called, thereby suppressing the output generated by these functions.

Using an interposer is the only way to globally disable this output, as GTK itself doesn't provide any mechanism to do this[^1]. The workarounds suggested in [^1] are suboptimal because they have to be applied individually to each GTK application. Piping or redirecting `stdout` to `/dev/null` also has to be applied to each individual application and could hide other output that may be caused by actual issues.

[^1]: [How to stop gedit (and other programs) from outputting GTK warnings and the like in my terminal?](https://askubuntu.com/questions/505594/how-to-stop-gedit-and-other-programs-from-outputting-gtk-warnings-and-the-like) (Ask Ubuntu)

Building
--------

glib-log-interposer has been written using the [Eclipse IDE](https://eclipseide.org/) and can be built from within that IDE using the standard GCC C compiler and C++ linker.

Before you can build glib-log-interposer, an additional dependency may need to be installed:
```
sudo apt install libglib2.0-dev
```
After a first-time successful build in the Eclipse IDE, your checkout should contain a `Debug` and/or `Release` subdirectory, depending on which configurations were built. From then on, you can also use the auto-generated `Makefiles` in these directories to build directly from the terminal by navigating to the respective directory and running `make`.

Installing
----------

After building the project, you should have a `libglib-log-interposer.so` shared library file. The `LD_PRELOAD` environment variable must contain the full path to this file for the library to be able to do its job. The easiest way to do this is to add the following line to the `.bashrc` file in your home directory:
```
export LD_PRELOAD=<full path to libglib-log-interposer.so>
```
If you want your `LD_PRELOAD` environment variable to contain multiple interposers, you can separate each interposer's filename with a colon.

Frequently asked questions
--------------------------

### Why is it called glib-log-interposer and not gtk-log-interposer?

While the applications that generate these debug messages are usually GTK applications, the functions that they internally use to generate these messages are all part of the [GLib library](https://docs.gtk.org/glib/), such as `g_log()`. Since this interposer only intercepts functions of the GLib library (and none that are part of the GTK library), it was decided to call it glib-log-interposer. Naming it gtk-log-interposer would give the impression that the interposer intercepts GTK functions and would therefore be misleading.

### Is there a quick way to enable these messages again without having to disable the interposer?

Yes, when the `GLIB_LOG_INTERPOSER_DISABLE` environment variable is defined and set to `1`, the interposer will allow GTK applications to write these messages to `stdout` again. This, for example, means that you can launch `gedit` from the terminal like this:
```
GLIB_LOG_INTERPOSER_DISABLE=1 gedit
```

### When running a 32-bit executable on my 64-bit Linux, I see an error stating that the interposer cannot be preloaded

If you see this error when running a 32-bit executable:
```
ERROR: ld.so: object '/lib/x86_64-linux-gnu/libglib-log-interposer.so' from LD_PRELOAD cannot be preloaded (wrong ELF class: ELFCLASS64): ignored.
```
Then that means that the Linux loader tried to preload the 64-bit version of the interposer into the address space of a 32-bit process. This is simply not possible: a 32-bit process can only load 32-bit shared libraries, and a 64-bit process can only load 64-bit shared libraries.

The solution is to also build the 32-bit version of the interposer, even though the operating system itself is 64-bit ('cross-compiling'). This may first require you to install some additional dependencies, as well as adding the `i386` architecture to `dpkg`:
```
sudo apt install g++-multilib \
                 gcc-multilib
sudo dpkg --add-architecture i386
sudo apt install libglib2.0-dev:i386
```
After that, set the active build configuration in Eclipse to the predefined `Release32b` or `Debug32b` configuration. Then you should be able to compile to 32-bit just as you would to 64-bit. The resulting 32-bit executable will be located in the `Release32b` or `Debug32b` subdirectory, respectively.

Additionally, you will also need to adapt your `LD_PRELOAD` environment variable so that it points to the 32-bit interposer for 32-bit executables, as explained in the next question.

### How can I define `LD_PRELOAD` for both 32-bit and 64-bit executables?

To be able to do this, both the 32-bit and 64-bit interposers should be located in predefined subdirectories where Linux expects them (`i386-linux-gnu` and `x86_64-linux-gnu`). The easiest way to do this is to define another environment variable, `GLIB_LOG_INTERPOSER_DEPLOY_DIR`.

When `GLIB_LOG_INTERPOSER_DEPLOY_DIR` is defined, the project's post-build script will take care of copying the compiled interposer file to the expected deploy subdirectory, depending on whether the build was 32-bit or 64-bit.

Note that if you define `GLIB_LOG_INTERPOSER_DEPLOY_DIR` in your `.bashrc` file, it must be placed **before** the existing `LD_PRELOAD` definition. Then you can simply refer to the former environment variable when defining the latter:
```
export GLIB_LOG_INTERPOSER_DEPLOY_DIR=interposers
export LD_PRELOAD=$GLIB_LOG_INTERPOSER_DEPLOY_DIR/'$LIB'/libglib-log-interposer.so
```
